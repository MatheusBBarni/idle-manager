# ADR-002: Don't-paint live views (spike-gated, fail-closed)

## Status

Accepted

## Date

2026-08-31

## Context

Product V1 is an invisible live-farm diet ([ADR-001](adr-001.md), `_prd.md`): 3–6 running accounts must keep ticking on a shared Windows PC; no Park chrome, no auto-sleep, no merged jars. If live sessions cannot cost less without pausing progress, ship nothing.

Today every `status === 'running'` account is a `WebContentsView` in the chrome window tree (`syncViews` / `applyStage`). Off-stage views call `setVisible(false)` but are not removed. Three process-wide Chromium switches plus window-global `backgroundThrottling: false` keep timers and Page Visibility awake.

This ADR locks the **implementation** approach. It does not replace ADR-001.

## Decision Drivers

- G-01 / F-01: other apps stay usable while 3–6 accounts remain running
- G-02 / F-02: no discard, sleep, or surprise reload; hidden and other-tab running accounts still progress
- G-03 / F-05: no new chrome; always-on; no snapshot/IPC/metrics change
- Isolation + `pnpm verify:isolation` unchanged
- Electron 37: `backgroundThrottling: false` is window-global; Page Visibility stays `visible` even when minimized/occluded/hidden
- Electron 37: native occlusion in Page Visibility is macOS-only; Windows hides on minimize/`hide()`, not on being covered
- User: main-process only; always-on; spike then fail-closed; existing CI gates only; don't-paint diet

## Decision

V1 is a **don't-paint diet** in `applyStage` / chrome window visibility, **after a Windows spike**:

1. **Keep** `disable-renderer-backgrounding`, `disable-background-timer-throttling`, `disable-backgrounding-occluded-windows`, and `backgroundThrottling: false`. Do not merge partitions. Do not `destroyView` for running accounts. Do not `loadURL` / reload to save RAM.
2. **Paint** a running, non-popped-out view only when it has a stage panel (current tab layout, not overlay, bounds ≥ 8px) **and** the chrome window is visible and not minimized.
3. **Otherwise** `setVisible(false)` and `removeChildView` if attached. `webContents` stay alive. Popped-out views stay painted in their `BrowserWindow`.
4. **Do not** treat `blur` as occlusion. Windows has no occlusion event that matches G-01 “other apps in front.”
5. **Spike (Windows), per knob, fail-closed:**
   - Knob 1: off-stage `removeChildView` (other tab / single layout / overlay).
   - Knob 2: chrome window minimized or `!isVisible()`.
   - Pass = Task Manager working set drops vs today’s attach-and-hide **and** a local fixture keeps `setInterval` firing **and** `document.visibilityState === 'visible'` (no game `executeJavaScript`).
   - Fail a knob → do not ship that knob. Fail both → ship no diet (PRD stop).
6. **No** new IPC, snapshot fields, metrics shape, preload, packages, or Electron CLI. Rollback is a code revert. Gates: `pnpm test`, `pnpm typecheck`, `pnpm verify:isolation`.

## Alternatives Considered

### Relax backgrounding switches

- **Benefits:** Might let Chromium purge occluded renderers globally.
- **Costs/risks:** Process-wide; may no-op while Page Visibility stays `visible`; higher G-02 risk.
- **Why not selected:** User chose A.

### Cache / V8 caps

- **Benefits:** Touches still-painted grids.
- **Costs/risks:** OOM, extra network, isolation/cache semantics; unlikely to free a 6-account farm.
- **Why not selected:** User chose A.

### Best-effort land without spike

- **Benefits:** Faster.
- **Costs/risks:** Can ship a no-op or a hidden G-02 break.
- **Why not selected:** User chose spike then fail-closed.

## Consequences

### Positive

- Paint cost can drop without a new operator state.
- Timer/visibility flags stay the idle-loop contract.
- Isolation and close-without-wipe unchanged.

### Negative and trade-offs

- A fully visible 6-panel grid (e.g. second monitor) still costs full GPU; V1 does not diet on-stage paint.
- Windows covered-but-not-minimized is not a knob.
- CI does not prove RAM or timers.
- Implementation waits on the spike.

### Risks and mitigations

- `removeChildView` backgrounds the renderer or flips visibility — fail that knob; do not “fix” it by enabling throttling.
- Minimize knob no-ops because visibility stays `visible` — ship off-stage only if that knob passed.
- Fake RAM win via frozen games — fixture + dogfood G-02; no `executeJavaScript` into game origins.

## Reversibility and Rollback

High. No persisted flag. Revert `views.ts` (and any minimize listeners). Partitions and workspace JSON untouched.

## Implementation Notes

- Prefer existing `views.ts`; no new directory or dependency.
- Do not inject into game documents.
- Crash path stays `restartView`.
- Overlay already hides views; use the same don't-paint path, not a new overlay.

## Follow-ups

- Packet spike journal before implementation tasks ship production diet code.
- Dogfood G-01 / G-02 on Windows after a passing knob ships.
