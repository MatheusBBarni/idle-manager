# ADR-004: Browser GitHub Releases probe; fail-open to `/releases/latest`

## Status

Accepted

## Date

2026-08-30

## Context

Live Download must point at a GitHub Release **asset file** when one exists (PRD US-03, TechSpec href A). The user rejected a build-time `WINDOWS_DOWNLOAD_URL` and chose a **browser fetch** of GitHub’s Releases API.

`GET https://api.github.com/repos/MatheusBBarni/idle-manager/releases/latest` currently returns **404**, with `Access-Control-Allow-Origin: *` and unauthenticated **60 req/hour/IP**.

PRD G-03 says nobody is offered a working Download before an installer exists. The user was shown that conflict and chose **always fall back**, including 404, to `https://github.com/MatheusBBarni/idle-manager/releases/latest`.

This ADR records that product-behavior change so it is not a silent weaken of G-03.

## Decision Drivers

- F-04 / US-03: Download starts the installer when an asset exists
- User: browser fetch of Releases API
- User: on any fetch failure including 404, fall back to `/releases/latest`
- G-04: no third-party analytics pixels (GitHub API is not a pixel; it is a third-party GET)
- No GitHub token in the static site

## Decision

A small client script on both locale pages:

1. `GET https://api.github.com/repos/MatheusBBarni/idle-manager/releases/latest` with `Accept: application/vnd.github+json`. No auth, no cookies beyond the browser default to GitHub.
2. If the JSON has a Windows installer asset (name ends with `.exe`), set Download `href` to `browser_download_url` and treat the control as **asset**.
3. Otherwise (404, 429, network error, malformed JSON, no `.exe` asset): set Download `href` to `https://github.com/MatheusBBarni/idle-manager/releases/latest` and treat the control as **fallback**.
4. Download is **always offered**. SmartScreen / unsigned warning is always visible with the control (F-05).
5. Asset picker is a pure function, unit-tested, no Electron.
6. Privacy copy must mention this GitHub API request in addition to Pages IP logs.
7. If a Content-Security-Policy is added, `connect-src` must allow `https://api.github.com`.

G-03 verification in this design: **not** “button hidden.” It becomes “href is never a missing file on our origin; empty state is GitHub’s Releases page.” Root `pnpm test` does not cover this; `pnpm --dir site test` does.

## Alternatives Considered

### Fail closed (withhold on 404)

- **Benefits:** Literal G-03.
- **Costs/risks:** Empty state has no Download.
- **Why not selected:** User chose always fallback after the G-03 warning.

### Build-time asset URL

- **Benefits:** No browser API, no 60/h limit.
- **Costs/risks:** Rebuild to enable.
- **Why not selected:** User chose browser fetch.

## Consequences

### Positive

- First Release can enable asset Download without editing site source.
- Outage still sends the player to GitHub Releases.

### Negative and trade-offs

- Before the first Release, Download opens an empty GitHub Releases page (accepted G-03 relaxation).
- Shared NAT IPs may 429; those users get fallback, not the asset.
- Visitor IP is visible to GitHub via the API call.

### Risks and mitigations

- Wrong asset picked (mac `.dmg`) — picker only `.exe` for V1.
- XSS from API JSON — use `href` from parsed `browser_download_url` only if it is `https://` on `github.com` or `objects.githubusercontent.com` / `release-assets.githubusercontent.com`; never `innerHTML` the payload.
- Rate limit — accept fallback; do not retry loops.

## Reversibility

High. Remove the script and hardcode withheld or a build-time URL. Requires a TechSpec/PRD note if G-03 is restored.

## Follow-ups

- Implement `selectWindowsDownload` tests for 404, empty assets, `.exe` present, non-https href rejected.
- Do not put a GitHub token in Actions for this public GET.
