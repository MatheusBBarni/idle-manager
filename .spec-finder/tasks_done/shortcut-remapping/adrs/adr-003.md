# ADR-003: Full snapshot shortcut map with per-command fallback

## Status

Accepted

## Date

2026-08-31

## Context

Custom binds must survive restart and ride Import workspace (PRD F-09, constraints). `WorkspaceSnapshot` is version 1; `parseSnapshot` already fail-closes unknown locale to `pt`. `exportMetadata` carries locale/theme, not `launchAtStartup`. The operator chose a **full** map on disk (every documented command always written) rather than sparse overrides, so later shipped-default changes do not rewrite existing files.

## Decision Drivers

- PRD F-09 / US-07 persistence; F-10 / G-05 defaults if never remapped
- PRD F-04 duplicate refused; no unbind
- User: full map on disk; `{ key, shift, alt }` with implied platform mod; per-command fallback
- `applyAction` is the only workspace mutation seam
- Game-list export must not carry binds

## Evidence

| Kind | Finding | Source | Version/date |
|---|---|---|---|
| Repository | Snapshot version 1; invalid locale → `pt` | `src/shared/workspace.ts` `parseSnapshot` | 2026-08-31 |
| Repository | Workspace export includes locale/theme | `exportMetadata` | 2026-08-31 |
| User decision | Full map; implied mod; per-command fallback; `prefs/shortcut` | TechSpec clarification B, A, A | 2026-08-31 |

## Decision

1. `WorkspaceSnapshot.shortcuts` is a full `Record<ShortcutCommand, ShortcutChord>`. Version stays 1.
2. Chord is `{ key: string, shift: boolean, alt: boolean }`. Ctrl vs Command is implied by OS. Legal live chords always include that platform mod (never persisted as a field).
3. `emptySnapshot()` writes shipped defaults. Old v1 files without `shortcuts` parse to current defaults; the next save persists the full map.
4. `prefs/shortcut` sets one command to a chord, or resets that command to its shipped default (still stored, not omitted). Illegal or taken chords no-op.
5. Parse: unknown commands ignored. Invalid chord or duplicate identity: that command (later duplicate in catalog order) becomes the shipped default. One bad row does not wipe the table.
6. `exportMetadata` includes `shortcuts`. Game-list documents do not.

## Alternatives Considered

### Sparse overrides

- **Benefits:** Smaller files; default changes apply until remapped.
- **Costs/risks:** User explicitly wanted frozen full maps after first write.
- **Why not selected:** User chose full map.

### Whole-map reset on any defect

- **Benefits:** Simpler parse.
- **Costs/risks:** One bad row wipes a week of remaps.
- **Why not selected:** User chose per-command fallback.

## Consequences

### Positive

- Restart and workspace import see the same table.
- Corrupt rows recover without deleting valid remaps.

### Negative and trade-offs

- After first save, changing shipped defaults in a release does not update existing workspaces (they already have a full map).
- Import workspace replaces the recipient’s map (same as locale/theme).

### Risks and mitigations

- Duplicate on import — parse fallback + `prefs/shortcut` no-op; unit tests.
- Slot family `1…9` — persist modifiers plus canonical `key: '1'`; match any digit 1–9.

## Reversibility and Rollback

- Ignore `shortcuts` on parse (always defaults) and stop writing the field. Existing files remain version 1.

## Implementation Notes

- Do not bump snapshot `version`.
- Do not log `key` values.
- Reset is write-default, not delete.

## Follow-ups

- None blocking. Layout `[` vs `{` matching for default loop chords stays the existing dual-key behavior unless capture stores `{`.
