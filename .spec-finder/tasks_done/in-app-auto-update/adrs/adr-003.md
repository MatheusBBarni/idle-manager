# ADR-003: electron-updater 6.x main process + IPC side channel

## Status

Accepted

## Date

2026-08-30

## Context

PRD V1 needs Windows obtain+apply without covering game panels or mutating the workspace snapshot. The app already uses Electron 37, electron-builder 26, GitHub Releases, and a metrics-style IPC side channel. Built-in `autoUpdater` is Squirrel on Windows; this packager is NSIS. electron-updater 6.8.9 is the current npm line compatible with builder 26 (`autoInstallOnAppQuit`). Builder 27 replaces that with `autoInstallEvent`.

## Decision Drivers

- G-01–G-05, F-01–F-08, US-01–US-05 — operator-timed Windows apply, silent empty paths
- ADR-001 — `verifyUpdateCodeSignature` stays true
- ADR-002 — chrome strip, not overlay
- `AGENTS.md` — no second workspace reducer; game views no preload
- User: `onUpdate` + `updateCommand('apply'|'later')`; Apply-only install; attach `latest.yml`; shared status tests

## Decision

Implement V1 with **electron-updater 6.x in main**, GitHub provider from existing `publish` config, **packaged `win32` only**.

- `autoDownload` default on; `autoInstallOnAppQuit: false`; only `updateCommand('apply')` calls `quitAndInstall`.
- Preload: `onUpdate` push + `updateCommand('apply' | 'later')`. No workspace fields.
- Shared pure status machine (idle / getting / ready / later) unit-tested; StatusBar maps ready → Apply/Later, getting → quiet copy, else version-only.
- Release keeps `--publish never`; attach Windows `latest.yml` and blockmap if produced; fail if missing.
- `verifyUpdateCodeSignature` remains true. Do not upgrade electron-builder to 27 in this slice.
- `pnpm verify:isolation` is a no-touch gate. Packaged apply is dogfood.

## Alternatives Considered

### Homegrown GitHub poll + spawn NSIS

- **Benefits:** No electron-updater pack/asar issues.
- **Costs/risks:** Reimplements feed, progress, checksum, publisher check.
- **Why not selected:** User A; higher unsigned-execute risk.

### electron-builder 27 + updater 7

- **Benefits:** `autoInstallEvent: 'manual'` is the newer API.
- **Costs/risks:** v27 publish/signing schema migration.
- **Why not selected:** Unrelated to Apply/Later; project is builder 26.

## Consequences

### Positive

- Matches NSIS + GitHub + existing IPC style.
- Snapshot/import/isolation unchanged.
- Window close cannot stealth-install.

### Negative and trade-offs

- CI does not prove GitHub download or NSIS apply.
- `files` + `externalizeDepsPlugin` must actually pack `electron-updater`.
- StatusBar density.

### Risks and mitigations

- Updater missing from asar — verify packed output includes it; adjust `files` if needed.
- Unsigned packaged Win still calls check, verify fails, stays idle — matches US-05.
- `latest.yml` forgotten — release job fails closed.

## Reversibility and Rollback

- Remove IPC + dependency; GitHub still has installers.
- Switching to builder 27 later is a separate ADR.

## Implementation Notes

- Do not use `checkForUpdatesAndNotify`.
- Flush workspace + views before `quitAndInstall`.
- Later is in-memory for the process; next launch may return to ready from updater cache.
- No `electron-log` unless packing already requires it; console is enough.
- i18n keys in both `en` and `pt`.
- Do not start the updater on darwin/linux.

## Follow-ups

- Confirm Windows `dist/` names for `latest.yml` / blockmap in the release glob.
- Signing env (`WIN_CSC_LINK` or equivalent) remains a ship gate, not this ADR.
