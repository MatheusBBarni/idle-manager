# ADR-003: Loop-only main before-input interceptor

## Status

Accepted

## Date

2026-08-30

## Context

PRD G-01 requires create / next / previous / start while a game panel is focused. Chrome shortcuts today are `window` `keydown` in `Shell.tsx`. Game documents are sandboxed `WebContentsView`s with no preload. `commit()` in main already applies `WorkspaceAction`. Menu is null. `globalShortcut` is forbidden.

## Decision Drivers

- PRD: loop keys while a game is focused; unmatched keys reach the game; no OS-global shortcuts
- User: main `before-input-event` matcher, not a hidden menu, not game-view IPC
- User: keyboard create = existing `account/create` then `account/activate` with a supplied id
- User: skip dispatch while overlay/dialog is open or chrome editable is focused
- User: chords `Mod+Shift+N`, `Mod+Shift+[`, `Mod+Shift+]`, `Mod+Enter`
- User: loop-only interceptor; do not migrate README shortcuts; do not double-register in `Shell.tsx`
- User: shared unit tests + typecheck; game-focus is dogfood
- AGENTS.md: mutations in `applyAction`; no Node/preload on game views
- Electron 37: `before-input-event` + `preventDefault` blocks page keys

## Decision

V1 design is a **loop-only main interceptor**:

1. A pure shared matcher maps keydown + modifiers to `account-create` | `account-prev` | `account-next` | `account-start` or `null`. Keyup and auto-repeat do not match. Bare keys never match.
2. Main attaches `before-input-event` to the chrome `webContents` and to every live game `webContents` (create, restart, pop-out contents that already share `attachSessionHandlers`). On match: `preventDefault`, then `commit` existing actions. Unmatched events are not prevented and not logged.
3. Create: `newId()`, `account/create` with empty name and that id, then `account/activate` with that id. Mouse dialog create is unchanged.
4. Next/prev: wrap over the active tab’s `accountOrder` (closed included) via a shared helper, then `account/activate`.
5. Start: `account/setStatus` `running` on the active account; no-op if missing, closed-tab, or already running.
6. Skip `commit` when `overlayOpen` is true or chrome focus is an editable. Game-view matches still commit.
7. `Shell.tsx` keeps current README shortcuts. Do not add the four loop chords there.
8. No new IPC, no `WorkspaceAction` types, no `globalShortcut`, no application menu.

Public chords (`Mod` = `CommandOrControl`):

| Action | Accelerator |
|---|---|
| Create | `CommandOrControl+Shift+N` |
| Previous | `CommandOrControl+Shift+[` |
| Next | `CommandOrControl+Shift+]` |
| Start | `CommandOrControl+Enter` |

## Alternatives Considered

### Hidden application menu accelerators

- **Benefits:** Native accelerator display.
- **Costs/risks:** Menu is null today; WebContentsView focus behavior undocumented; still need preventDefault.
- **Why not selected:** User chose A.

### Renderer match + game IPC

- **Benefits:** Stays in Shell.tsx.
- **Costs/risks:** Game views have no preload.
- **Why not selected:** Isolation; user rejected C.

### Always-activate `account/create` / new action type

- **Benefits:** One commit.
- **Costs/risks:** Mouse create steals active, or a second verb.
- **Why not selected:** User chose create-then-activate.

### Intercept all README shortcuts now / dual Shell+main registration

- **Benefits:** One input path / chrome still works if main fails.
- **Costs/risks:** PRD out of scope / double dispatch.
- **Why not selected:** User chose loop-only interceptor.

## Consequences

### Positive

- Loop works with a game focused without a preload on guest views.
- Matcher and wrap helper are unit-testable in `src/shared`.
- Mouse create and existing chrome shortcuts stay as they are.

### Negative and trade-offs

- Existing README shortcuts remain chrome-only.
- CI will not prove guest-focus routing.
- Four reserved chords never reach the game.

### Risks and mitigations

- Listener forgotten on `restartView` — attach in `attachSessionHandlers` used by create/restart/pop-out.
- Double fire if chrome and a view both see the event — only the focused `webContents` emits `before-input-event`.
- Overlay skip misses URL bar — treat chrome editable as skip on the chrome contents path.

## Reversibility

High. Remove listeners and Settings/README/landing rows. No snapshot schema change.
