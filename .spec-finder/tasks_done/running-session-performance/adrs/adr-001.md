# ADR-001: Honest cost, then quieter farm

## Status

Accepted

## Date

2026-08-31

## Context

A Windows operator who tiles about 3–6 isolated idle-game logins on a shared PC hits machine pressure. Each running account is a live isolated session that must keep progressing. Closing a panel already drops that session’s view and keeps the login. Chrome-style Memory Saver would deactivate unused tabs and reload them, which stops idle progress.

`live-account-ram` chose an invisible cheaper farm with no cost chrome, no cap, and no Park. That packet completed as a fail-closed non-ship (Windows evidence never ran). Farm vs PC is still the failure.

This ADR records the product approach for `running-session-performance`. It does not lock process, throttle, or view implementation.

## Decision Drivers

- User: failure is farm vs PC, not chrome jank alone
- User: primary operator is a small live farm (about 3–6 accounts, one or two games) on a shared Windows PC
- User: success is a before/after dogfood journal (3-account and 6-account); operator does not close panels just to free the machine; running still ticks
- User: auto-sleep, auto-discard, named Park, and merging jars are out
- User: operator-visible cost chrome is allowed because the chrome-less diet shipped nothing
- User: start bound is a warning, not a lock; 3–6 starts stay unblocked
- User: selected approach A — honest machine cost, then a Windows-gated quieter live farm
- Repository: RAM is already shown but omits GPU; FPS is the shell loop; close already destroys the view; off-stage running accounts still cost a live session
- External: Chrome Memory Saver reloads deactivated tabs; Chromium isolation costs memory; Electron says measure first; throttling-off keeps pages visible

## Decision

V1 ships **truthful machine cost** in existing chrome (including GPU; do not pass shell FPS off as the games), then a **Windows-gated quieter live farm** only if running accounts still tick, plus a **warning** when starting beyond the 3–6 farm (not a hard cap).

Out: auto-sleep, discard/reload, named Park, merged cookie jars, hard blocked Start, macOS as the success gate.

If the quieter farm cannot be evidenced without pausing ticks, V1 still ships cost chrome and the start warning. It does not ship a fake diet or invent Park to hit G-01.

## Alternatives Considered

### Quieter farm first (approach B)

- **User value:** Nothing new to learn if the diet works
- **Costs/risks:** Repeat of `live-account-ram`: diet fails, packet ships little
- **Why not selected:** User chose A; chrome-less diet already completed as a non-ship

### Warnings first (approach C)

- **User value:** Operator notices over-start even when diet never works
- **Costs/risks:** Six running accounts can still wreck the PC; we mostly nag
- **Why not selected:** User chose A; G-01 is farm usability at 3–6, not only blocking the 7th

### Invisible diet with no cost chrome (`live-account-ram` ADR-001)

- **User value:** Same start / close / tile
- **Costs/risks:** No lever when diet does not ship
- **Why not selected:** That packet already ran; this packet exists because farm vs PC remains

## Consequences

### Positive

- Operator can judge the PC from chrome (G-03) even if diet evidence fails
- Quieter farm cannot ship a frozen-game “win” (G-02 + F-07)
- 3–6 starts stay easy; over-start is visible (G-04)

### Negative and trade-offs

- New chrome to read (reverses `live-account-ram` “nothing to learn”)
- Two surfaces (readout + optional diet) instead of one invisible change
- Hard cap and Park deferred; G-01 may still miss on a 6-account Unity-class farm

### Risks and mitigations

- Diet impossible without pause — Fail-closed (F-07); ship F-05/F-06; no stealth Park
- Readout still understates GPU — G-03 journal vs Task Manager
- Warning ignored — Out of scope to hard-cap unless a new ADR

## Reversibility

- Hide extra metrics or drop the warning without touching isolation
- Revisit a hard cap or Park only with a new ADR if the journal shows G-01 missed because of over-start or because live sessions cannot get cheaper
- Evidence that would trigger revisit: Windows journal where 3–6 still force close-for-RAM after a failed diet, or operators routinely start 12+
