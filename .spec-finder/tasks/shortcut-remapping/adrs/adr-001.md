# ADR-001: Settings Shortcuts tab for documented modifier chords

## Status

Accepted

## Date

2026-08-31

## Context

Idle manager already ships a mouse-free account loop on four frozen modifier chords, plus a larger chrome-only README shortcut set. Settings lists the four loop binds as read-only. Operators who already have Chrome-class muscle memory do not relearn those frozen chords, so they keep using the mouse for actions that already have keys.

The previous packet (`keyboard-shortcuts`) deferred remapping unless a reserved chord collided with a game. This packet is not that escape hatch. The verified need is matching existing habits so the operator adopts the keyboard loop.

## Decision Drivers

- User: failure is muscle-memory mismatch, not game collision
- User: primary user is the multi-account operator with existing keyboard habits; casual players keep mouse paths
- User: success is ~1 week dogfood — remap, then mouse-free create → cycle → start
- User: V1 remaps every documented keyboard action, not only the four loop binds
- User: modifier chords only
- User: approach A — Settings Shortcuts tab; click and press; duplicate refused; per-row reset; no unbind; public docs stay defaults; chrome remaps stay chrome-focused; `Mod+1…9` is one family

## Decision

V1 is a **Settings Shortcuts tab** where the operator remaps **every documented keyboard action** to a **modifier chord**:

1. Existing Settings gains a Shortcuts tab beside the current general pane (language, theme, startup, import/export).
2. The tab lists each documented action with its current chord. The operator clicks a row and presses a new modifier chord.
3. A chord already used by another listed action is refused. The occupying row stays put. There is no unbind-to-empty.
4. Each row can reset to the shipped default.
5. Loop actions keep working while a game panel is focused. Chrome-only actions stay chrome-focused.
6. `Mod+1…9` stays one slot-jump family (one remappable modifier; digits 1–9 stay the slot). Bare keys are not allowed.
7. Public keyboard docs and README keep shipping **defaults**, not this operator’s map.
8. Custom binds persist across sessions on this workspace, like other Settings prefs.

## Alternatives Considered

### Loop-only remap

- **User value:** Smallest collision/habit fix for create / prev / next / start.
- **Costs/risks:** Chrome actions stay frozen and hidden from the editable list.
- **Why not selected:** User chose all documented binds.

### Editable list in the existing Settings modal (no tab)

- **User value:** Less chrome structure.
- **Costs/risks:** The modal already stacks language, theme, startup, a shortcut list, and four import/export actions.
- **Why not selected:** User chose a Shortcuts tab.

### Unbind plus last-assignment-wins

- **User value:** Faster swap; Wavebox-like.
- **Costs/risks:** Create/start can end with no key; another action can be silently stolen.
- **Why not selected:** User chose refuse-duplicate and no unbind.

## Consequences

### Positive

- Operators can keep Chrome-class habits for both the account loop and documented chrome actions.
- Lookup and edit live in one Settings tab.
- Game typing stays on unmatched keys because only modifier chords are legal.

### Negative and trade-offs

- Swapping two chords needs a spare modifier chord as a parking spot (no unbind, no steal).
- Remapping reload/mute/new tab does **not** make those keys work while a game panel is focused.
- Public docs will not match a customized machine.
- Casual players who open the tab can change binds; they are not the design center.

### Risks and mitigations

- Operator remaps a chrome action and expects it during play — dogfood G-02; copy in the tab can separate loop vs chrome-only. Reopen focused-chrome-port only if that journal fails.
- Duplicate-refuse makes swaps awkward — document the parking-spot path; reopen unbind/steal only if dogfood cannot complete a wanted swap.
- Custom map in workspace export surprises a recipient — same as today’s locale/theme on Import workspace; game-list pack stays binds-free.

## Reversibility

High. The tab can return to a read-only list and ignore stored maps without taking default keys away. Dropping chrome rows from the tab does not require dropping loop remap.

## Follow-ups

- Dogfood: remap then mouse-free loop (~1 week).
- Reconsider unbind/steal if swaps fail that week.
- Reconsider chrome-under-game-focus if remapped chrome actions still force a chrome click after G-02.
