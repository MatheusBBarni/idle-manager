# ADR-002: Shared shortcut catalog with dual dispatch paths

## Status

Accepted

## Date

2026-08-31

## Context

Remapping must drive both the account-loop interceptor (game + chrome `before-input-event`) and the chrome-only `Shell.tsx` `keydown` table. Settings overlay sets `overlayOpen`, so the loop interceptor ignores keys while the operator captures a chord. Unifying every README action onto the interceptor would satisfy one matcher but can `preventDefault` chrome chords on a focused game if scope is wrong. Product forbids chrome remaps from starting to work during play.

## Decision Drivers

- PRD F-06 / F-07: loop remaps while a game is focused; chrome remaps chrome-only
- PRD F-03 / US-04: click-press capture; illegal/duplicate leave the row unchanged
- Isolation: no preload on game views; no `globalShortcut`
- Overlay skip already on the loop interceptor (`accountLoop.ts`, `Stage.tsx`)
- User: approach A — shared catalog, keep both live paths, renderer capture

## Evidence

| Kind | Finding | Source | Version/date |
|---|---|---|---|
| Repository | Loop matcher frozen; interceptor skips overlay | `src/shared/accountLoop.ts`, `src/main/accountLoop.ts` | 2026-08-31 |
| Repository | Chrome binds hardcoded on `window` keydown | `src/renderer/src/components/Shell.tsx` | 2026-08-31 |
| Official docs | `before-input-event` + `preventDefault` blocks the page | Electron 37.10.3 webContents | 2026-08-31 |
| User decision | Shared catalog, dual paths, renderer capture | TechSpec approach A, capture A | 2026-08-31 |

## Decision

1. One shared catalog, chord type, matcher, and conflict identity in `src/shared` (not a second copy in Shell).
2. Loop commands keep the existing main interceptor attach points. Chrome commands stay in `Shell.tsx`. Both call the shared matcher with an explicit scope (`loop` | `chrome`).
3. Capture runs in the Settings Shortcuts tab. Overlay skip for the interceptor stays. While capturing, Shell does not dispatch. Escape cancels capture only.
4. No new IPC, no game-view preload, no `globalShortcut`, no application menu accelerators.

## Alternatives Considered

### Unify all documented actions on `before-input-event`

- **Benefits:** One live listener.
- **Costs/risks:** Scope bug steals game keys for reload/new-tab; larger `views.ts` change.
- **Why not selected:** User chose dual paths.

### Parameterize loop only; handwritten chrome table

- **Benefits:** Smaller Shell diff.
- **Costs/risks:** Conflict identity drifts between paths.
- **Why not selected:** User rejected approach C.

## Consequences

### Positive

- Game-focused loop remaps reuse the proven interceptor.
- Chrome remaps cannot `preventDefault` on guest contents.
- Capture does not fight overlay skip.

### Negative and trade-offs

- Two listeners must use the same chord identity.
- Capturing flag is renderer-local, not snapshot state.

### Risks and mitigations

- Shell fires during capture — capturing flag short-circuits dispatch (US-04).
- Matcher drift — one shared function; unit tests own identity.

## Reversibility and Rollback

- Revert Shell and interceptor to frozen defaults; ignore snapshot map.
- No partition/session change; `verify:isolation` not required unless attach hooks change beyond reading the map.

## Implementation Notes

- Do not attach chrome-scoped commands on game contents.
- Do not lift overlay skip to capture chords.
- HeroUI v3 `Tabs` compound components for General vs Shortcuts.

- Dogfood G-01 guest-focus after remap (CI cannot prove it).
