# ADR-001: Settings game-list pack, additive load

## Status

Accepted

## Date

2026-08-31

## Context

Idle manager already has Settings → Export / Import workspace. That file is a full-workspace swap: tab names/URLs/layouts **and** account names, colors, and URLs. Cookie jars are not in the file. Import replaces the whole workspace with no confirm and closes every session.

The verified failure is not “missing export.” A friend or new operator cannot receive a **game-tab starter pack** without also receiving account identity records, and today’s Import is the wrong tool for that handoff.

V1 is that pack: in-bar tab names and URLs only, loaded by adding games. Accounts stay local and never appear in the file.

## Decision Drivers

- Need: carry/share the game-tab list with no account records
- Primary user: friend / new operator receiving a starter pack
- Success: one real handoff in ~1 week; recipient sees pack tabs and zero accounts from the file
- Non-goals: jars, running/closed, mute/zoom/pop-out, locale/theme, cloud; today’s workspace Export is not the pack
- Load: additive; existing tabs and accounts stay; duplicate URLs allowed
- Pack contents: every tab currently in the bar (not archived); one-click export
- Smallest credible V1: Settings actions only; no empty-app CTA; no confirm on workspace Import

## Decision

V1 is a **separate game-list pack in Settings**, not a change to workspace Export/Import:

1. The operator can export every **in-bar** tab (name + URL) to a file. Archived tabs stay out. Account records never go in the file.
2. The recipient can import that file. New game tabs are **added**. Existing tabs and accounts are not deleted, closed, or replaced. Duplicate names and URLs are allowed.
3. Workspace Export / Import stay as they are, including the unconfirmed full replace. V1 does not add a pack preview, a game picker, or an empty-bar “Load game list” control.
4. A malformed or empty pack does not create accounts and does not wipe the recipient’s workspace.

Cookie jars, running/closed, mute, zoom, pop-out, locale, theme, and cloud sync stay out.

## Alternatives Considered

### Pack plus a confirm on today’s Import workspace (approach B)

- **User value:** Wrong click on Import workspace is less lethal.
- **Costs/risks:** Extra friction on a path power users already use; larger V1 than the handoff needs.
- **Why not selected:** User chose A; workspace Import is explicitly unchanged.

### Empty-app load path (approach C)

- **User value:** Friend can load a pack without finding Settings.
- **Costs/risks:** More chrome; they can still hit workspace Import later.
- **Why not selected:** User chose the smaller Settings-only V1.

### Use today’s workspace Export as the pack (rejected in clarification)

- **User value:** One file, one pair of buttons.
- **Costs/risks:** Ships account names/colors/URLs; Import replaces the workspace.
- **Why not selected:** Contradicts the verified need and the non-goals.

## Consequences

### Positive

- A friend can receive games without account identity metadata.
- Additive load matches Chrome’s bookmark convention and will not delete the recipient’s jars.
- Today’s full-workspace backup path remains for operators who still want it.

### Negative and trade-offs

- Two export/import pairs in Settings. The friend can still click Import workspace.
- No first-run control; the recipient must open Settings.
- Sender cannot curate a subset; archived games are omitted.
- Duplicate games are possible if the recipient already added the same URL.

### Risks and mitigations

- Wrong-click Import workspace — Accepted for V1; reconsider if the dogfood handoff fails because of it (approach B).
- Sender exports the workspace file by habit — Copy must distinguish “game list” from “workspace.” Reconsider a preview if G-01 misses.

## Reversibility

- Confirm on workspace Import (approach B) or an empty-bar load (approach C) can be added without taking the pack away.
- Trigger: the one-week handoff fails because the friend cannot find Import game list, or uses Import workspace instead.

## Follow-ups

- Dogfood one real sender → recipient handoff (G-01).
- Do not treat workspace Import confirm or empty-bar CTA as silent scope.
