# ADR-002: Game-list helpers in workspace.ts, IPC twins, tab/create import

## Status

Accepted

## Date

2026-08-31

## Context

PRD + ADR-001 require a Settings **game-list pack** separate from workspace Export/Import: in-bar name+URL, additive load, no accounts. Workspace IPC and `snapshotFromImport` must stay. `parseSnapshot` treats anything without `version: 1` + `tabs` + `accounts` as `emptySnapshot()`, and workspace import assigns that — a pack that looks like a workspace would replace jars.

Canonical tab creation is `tab/create` (new UUID, `layout: 'grid'`, empty `accountOrder`, steals `activeTabId`). Vitest only covers `src/shared`. Electron 37 dialogs already back workspace export/import.

## Decision Drivers

- New public IPC, not a `kind` flag on `ops:export` / `ops:import`
- Distinct on-disk document, not `parseSnapshot`-valid, never contains `accounts`
- Import via `commitAll` of `tab/create`; restore prior in-bar `activeTabId`
- Silent fail-closed: malformed/wrong-kind/workspace JSON → no mutation, `false`; skip non-http(s) rows
- Prefer existing `workspace.ts` over a new module
- No Electron unit tests; no `verify:isolation` (partitions untouched)

## Decision

1. Add `exportGameList` / `parseGameList` / `gameListImportActions` in `src/shared/workspace.ts`.
2. On-disk document: `{ version: 1, kind: 'game-list', tabs: [{ name, baseUrl }] }`. Reject if `kind` is missing or not `'game-list'`, if `accounts` is present, or if JSON is not this shape. Export only `visibleTabs` name+URL (no ids, layout, archived, accounts).
3. `OpsourceAPI.exportGameList` / `importGameList` → `ops:exportGames` / `ops:importGames`. Workspace channels unchanged.
4. Import applies `commitAll(gameListImportActions(...))`. Actions are `tab/create` (no supplied id) plus `tab/activate` of the previous in-bar active tab when one existed. Empty bar: last create stays active.
5. Cancel, IO/parse failure, wrong document, or zero valid URLs: return `false`, do not assign `snapshot`. No error dialog. Skip rows that fail `isValidHttpUrl`.
6. Settings gains two buttons and PT/EN strings distinct from workspace export/import. Default save name `idle-manager-games.json`.

## Alternatives Considered

### Kind argument on existing IPC

- **Benefits:** Fewer methods.
- **Costs/risks:** Changes the frozen workspace contract (G-03).
- **Why not selected:** User chose new IPC.

### `src/shared/gameList.ts`

- **Benefits:** Keeps `workspace.ts` from owning two documents.
- **Costs/risks:** Extra module for the same functions.
- **Why not selected:** Approach A; prefer existing module.

### Main-only parse

- **Benefits:** No shared schema types.
- **Costs/risks:** Pack contract untested in Vitest.
- **Why not selected:** Approach C rejected.

### `tabs/importPack` action / last-create steals active

- **Benefits:** One action, or zero restore logic.
- **Costs/risks:** Forks tab rules, or hides a live farm.
- **Why not selected:** User chose create-then-restore.

## Consequences

### Positive

- Pack cannot be applied through `snapshotFromImport`.
- Additive load reuses the only tab-create path.
- Shared tests can prove no accounts in the file and no wipe on junk.

### Negative and trade-offs

- `workspace.ts` owns workspace snapshot **and** game-list document.
- Two Settings pairs; wrong-click Import workspace still wipes (ADR-001).
- Silent skip does not explain a bad file.

### Risks and mitigations

- Workspace JSON passed to game-list import — `parseGameList` rejects `accounts` / wrong kind; no mutation.
- Game-list JSON passed to workspace import — still empty-snapshot wipe; out of scope to change.

## Reversibility and Rollback

- Remove the two IPC methods, Settings buttons, and helpers. Workspace export/import remain. Pack files on disk are unused.

## Implementation Notes

- Do not supply `id` on imported `tab/create` (mint UUID).
- Do not call `clearAccountSession` / `accountIdsToWipe` on this path.
- Do not log pack contents.
- Do not change `exportMetadata`, `parseSnapshot`, or `ops:export` / `ops:import`.
