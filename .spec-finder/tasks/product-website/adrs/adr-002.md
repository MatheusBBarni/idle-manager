# ADR-002: Dual-state player page (public now, download later)

## Status

Accepted

## Date

2026-08-30

## Context

Approved `_idea.md` and ADR-001 already require one public landing and a Windows download CTA that is live only when a same-repo GitHub Release installer exists. The PRD still needed an explicit product approach for what visitors see in each state, plus three scope calls: non-Windows path, language, and accessibility.

GitHub still has `releases: []` (API 2026-08-30). A live Download would fail the 30-day success test. The idea had listed PT/EN site localization as a V1 exclusion; PRD clarification overrode that for **one landing with Portuguese and English copy**, not a docs hub.

## Decision Drivers

- Verified problem: README is a contributor path; players cannot start a Windows install
- User: page live, download withheld until an installer exists
- User: Windows download when live; GitHub/source for non-Windows
- User: Portuguese and English on V1 (overrides idea exclusion of a localized hub)
- User: keyboard-usable page, not a formal WCAG AA public statement
- User: dual-state one page as the PRD approach
- SmartScreen warns on unknown/unsigned downloads ([Microsoft](https://learn.microsoft.com/en-us/windows/security/operating-system-security/virus-and-threat-protection/microsoft-defender-smartscreen/))
- GitHub Pages logs visitor IPs for security ([GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages))

## Decision

V1 is a **dual-state one-page player home**:

1. The public page may be live before an installer exists. In that state, Download is not offered (hidden or clearly unavailable). Isolation vs bot remains readable.
2. When a real Windows installer exists on the same GitHub project’s Releases, Download becomes the Windows path and carries an unsigned / unknown-publisher / SmartScreen warning.
3. Non-Windows visitors get GitHub/source, not a fake installer. GitHub/source may also be present as provenance for everyone.
4. Copy ships in **Portuguese and English** on that one page (not extra doc routes).
5. The page is operable without a mouse (keyboard, text for meaningful images, usable contrast). No separate accessibility statement in V1.
6. No third-party analytics pixels. Privacy copy covers app (local sessions) and site (host IP logging).

The 30-day first-visit download goal **starts when Download becomes live**, not when the page first appears.

## Alternatives Considered

### Page is not done until install works

- **User value:** “Shipped” always means a player can install.
- **Costs/risks:** Packaging blocks calling the work done; contradicts “page live, download withheld.”
- **Why not selected:** User chose dual-state A after choosing withheld-download A.

### One page plus in-page FAQ

- **User value:** Extra isolation/unsigned/local-session Q&A on the same URL.
- **Costs/risks:** More copy to keep true; no evidence FAQ is required for first-visit success.
- **Why not selected:** User chose the smaller dual-state page.

### English-only V1 (approved idea exclusion)

- **User value:** Less copy to maintain.
- **Costs/risks:** Portuguese-first players wait.
- **Why not selected:** User explicitly overrode the idea exclusion for PT and EN on the one landing.

## Consequences

### Positive

- A shareable player URL can exist without a dead Download.
- Isolation vs bot is available before packaging is ready.
- PT and EN match in-app languages without becoming a docs hub.

### Negative and trade-offs

- Early visitors cannot install; some will bounce.
- Two language copies must stay aligned with README privacy/isolation claims.
- Unsigned Windows builds will still face SmartScreen; the page warns, it does not remove the OS dialog.

### Risks and mitigations

- Dead or fake Download — withhold the control until a real Release asset exists.
- Localization drift — same claims in PT and EN; no extra routes to drift.
- Privacy contradiction — no extra trackers; disclose host IP logging vs local app sessions.

## Reversibility

High. Download can be enabled later on the same page. PT or EN can be dropped. A formal accessibility statement can be added later without changing the dual-state model.

## Follow-ups

- Enable Download only after a Windows installer exists on GitHub Releases.
- Start G-02’s 30-day window at that enablement, not at first page publish.
- TechSpec may choose how PT/EN is switched; this ADR only requires both languages on V1.
