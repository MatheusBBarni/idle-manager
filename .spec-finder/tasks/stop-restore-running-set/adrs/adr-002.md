# ADR-002: Atomic farm verbs in the workspace reducer

## Status

Accepted

## Date

2026-09-01

## Context

Last-set is “the accounts that were running the last time any panel was live.” `commitAll` applies `WorkspaceAction`s one by one. Today’s Start all loops `account/setStatus`. If bulk stop were the same loop, last-set would shrink to the last account closed. Workspace mutations belong in `applyAction`; React/main must not fork tab/account rules. Last-set must survive quit, must not ride workspace export, and must drop deleted ids.

## Decision Drivers

- PRD F-01–F-04, F-07; G-02 last non-empty farm
- AGENTS.md: canonical logic in `src/shared/workspace.ts`
- Existing `commitAll` + `syncViews` after a batch
- Snapshot v1 already gained `shortcuts` without a version bump
- Loop chords work via `before-input-event` (`accountLoop.ts`); new verbs are loop-scope

## Decision

1. Add `lastRunningAccountIds: string[]` to `WorkspaceSnapshot` v1. Missing/invalid parse → `[]`. Omit from `exportMetadata`. `snapshotFromImport` sets `[]`.
2. Last-set algebra lives in `applyAction`: after any status/membership change, if any account is running, last-set is those ids; if the farm just went empty, last-set is the ids that were running before the action; then drop ids with no account.
3. New actions, one commit each: `account/stopTab` `{ tabId }`, `account/stopFarm`, `account/restoreLastSet`. Close uses the same per-account rule as `account/setStatus` `'closed'` (pop-out clears). Restore sets `'running'` on still-existing last-set ids that are closed. Identity no-op when nothing changes.
4. Start all stays a renderer loop of `account/setStatus` (G-05).
5. Three `LOOP_COMMANDS`: `account-stop-tab` Mod+W, `account-stop-farm` Mod+Shift+W, `account-restore-last` Mod+Shift+Enter. Interceptor maps to the three actions. Settings catalog + README. No new IPC, snapshot version, module, or game preload.

## Alternatives Considered

### Loop `account/setStatus` like Start all

- **Benefits:** No new action types.
- **Costs/risks:** Bulk stop freezes last-set as the last closed id unless React forks the rule.
- **Why not selected:** User chose atomic actions.

### `src/shared/farmSession.ts`

- **Benefits:** Isolates last-set tests.
- **Costs/risks:** Extra module for three verbs.
- **Why not selected:** User chose fold into `workspace.ts`.

### Atomic Start all too

- **Benefits:** Symmetric commits.
- **Costs/risks:** Extra action not required by G-05.
- **Why not selected:** User chose not to expand Start all.

### Persist last-set only in memory / include in export

- **Benefits:** Smaller snapshot or portable farm memory.
- **Costs/risks:** Quit loses morning restore; or a workspace file restores a foreign farm.
- **Why not selected:** User chose snapshot, omit export, clear on import.

## Consequences

### Positive

- Bulk stop freezes the real farm, not the last panel.
- Morning restore survives quit without leaking through export.
- Keyboard uses the existing loop interceptor.

### Negative and trade-offs

- `workspace.ts` grows.
- Mod+W while a game is focused is reserved (Chrome-class close analog, but it stops panels, not a tab).
- Start all remains a multi-commit loop (last-set still converges once all are running).

### Risks and mitigations

- Interceptor no-op currently does not `preventDefault` — keep that rule so empty stop does not steal keys unless an action is produced; stop/restore still emit an action when there is work.
- Chord collision — remappable; listed in Settings.

## Reversibility and Rollback

- New snapshot field is ignored by older builds; new builds default `[]`.
- Removing the three actions leaves `account/setStatus` and Start all as today.

## Implementation Notes

- `accountIdsToWipe` must not treat stop/restore as deletes.
- Do not bump snapshot `version`.
- Do not switch `activeTabId` on restore unless a later PRD says so.
- i18n in all four dictionaries.
- Unit tests in `workspace.test.ts` and `shortcuts.test.ts`; gates `pnpm test` and `pnpm typecheck`. `verify:isolation` unchanged.
