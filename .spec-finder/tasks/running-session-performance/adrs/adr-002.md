# ADR-002: Metrics chrome + don’t-paint

## Status

Accepted

## Date

2026-08-31

## Context

PRD ADR-001 requires truthful machine cost, a Windows-gated quieter live farm, and a 7th-start warning that does not block. The chrome already has `ops:metrics` and a status bar. Confirm dialogs set `overlayOpen`, which hides game views. `live-account-ram` already specified don’t-paint detach and completed as a non-ship when Windows evidence could not run.

This ADR records the implementation approach. It does not change product scope.

## Decision Drivers

- User: widen `MetricsPayload` on existing `ops:metrics`
- User: no new persisted workspace fields
- User: split fail-closed (metrics always; diet spike-gated)
- User: shared tests + existing gates; diet journal not CI
- User: design A — metrics chrome + don’t-paint, not shell-only diet or hidden-view throttle
- PRD: cost chrome in sidebar/status, not over the stage
- Repository: Vitest is `src/shared` only; isolation CLI; no second reducer

## Decision

Implement V1 as:

1. Widen `AggregateMetrics` with whole-app totals and nullable GPU fields; `fps` is `null`; remove the chrome rAF meter.
2. Derive `shouldWarnRunningStart(runningCountBeforeStart >= 6)` in shared code; show it in status/sidebar only; never block start; never persist.
3. Don’t-paint with `shouldPaintGameView` + `removeChildView` **only** for Windows spike knobs that pass (off-stage detach; minimize/hide detach). Keep Chromium anti-throttle switches and game `backgroundThrottling: false`.

If both knobs fail, production paint policy stays as today. Metrics and the warning still ship.

## Alternatives Considered

### New diagnostics IPC

- **User value:** Leave old payload alone
- **Costs/risks:** Two streams for one status bar
- **Why not selected:** User chose widen `MetricsPayload`

### Shell-only diet

- **User value:** No game-view risk
- **Costs/risks:** 3–6 game renderers stay expensive (G-01)
- **Why not selected:** User chose don’t-paint

### Throttle hidden game views

- **User value:** Possible CPU drop
- **Costs/risks:** Page Visibility / rAF may stop idle ticks (G-02)
- **Why not selected:** User rejected; PRD forbids pause

## Consequences

### Positive

- Cost chrome ships even when diet cannot
- Warning cannot cover the stage
- Diet cannot ship a frozen-game win

### Negative and trade-offs

- Main and renderer must ship together (payload shape)
- G-01 RAM drop still not in CI
- `fps: null` removes a status number operators already see

### Risks and mitigations

- GPU missing — `null`, never fake `0`
- Spike environment Darwin — knobs fail; no paint-policy ship
- Overlay warning — forbidden by contract

## Reversibility

- Revert `MetricsPayload` consumers and restore rAF (not recommended)
- Revert `views.ts` independently of metrics
- Add a hard cap only with a new product ADR
