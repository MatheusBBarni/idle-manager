# ADR-002: Snapshot-derived keep-awake

## Status

Accepted

## Date

2026-09-01

## Context

PRD ADR-001 requires blocking OS idle sleep while any account is `running`, a status-bar hint, and release when none are running (or the app quits). Screen may sleep. The snapshot already stores `status`. Chrome already derives running count without extra IPC. Electron 37 exposes main-process `powerSaveBlocker` with `prevent-app-suspension` (system awake, display may off). Vitest cannot load Electron.

## Decision Drivers

- F-01–F-07, G-02 wording: hint iff ≥1 running, not iff OS ack
- No new snapshot field or Settings toggle (PRD)
- Prefer existing modules; do not touch `views.ts` partitions
- User: all-OS blocker + hint; Windows journal is G-01
- User: failed `start` → log, retry on next snapshot sync, hint still from running count
- User: shared tests + typecheck + isolation; no Electron CI, no idle-timer spike as ship gate
- User: technical approach A

## Decision

Keep-awake is **derived from the workspace running set**.

- Shared pure `hasRunningAccount(snapshot)` (running includes popped-out / other-tab).
- Main holds **one** `powerSaveBlocker` id, type **`prevent-app-suspension` only**, synced after every snapshot write path and after load. `stop` on `before-quit` and when the running set is empty.
- StatusBar shows a `role="status"` i18n hint when the predicate is true. No `OpsourceAPI` change, no snapshot field, no `WorkspaceAction`, no new package.
- Failed `start`: log, clear the stored id, retry on the next sync. Hint still follows the predicate.
- Do not edit `views.ts` isolation, Chromium switches, or `backgroundThrottling`.

## Alternatives Considered

### Blocker inside `syncViews` (approach B)

- **Benefits:** One call site already on load/import/commit
- **Costs/risks:** Power policy in the isolation-sensitive view file
- **Why not selected:** User chose A; keep `views.ts` off this packet

### IPC `sleepBlocked` side channel (approach C)

- **Benefits:** Hint matches `isStarted`
- **Costs/risks:** New chrome contract; fights G-02 and failure A
- **Why not selected:** User chose A

## Consequences

### Positive

- No persist/migration; hint and blocker share one predicate
- Isolation files and IPC stay untouched
- Unit tests stay in `src/shared`

### Negative and trade-offs

- Hint can claim blocked when `start` failed until the next snapshot sync
- Overnight idle-timer proof is dogfood, not CI
- macOS close-window (views destroyed, snapshot still running) keeps the blocker — not the V1 gate

### Risks and mitigations

- Leaked blocker id — single id, stop on empty set and `before-quit`
- Isolation regression — do not touch partitions / `views.ts`
- `prevent-display-sleep` by mistake — contract forbids that type

## Reversibility and Rollback

- Revert the shared helper, main module, StatusBar span, and i18n keys. No disk format change.

## Implementation Notes

- Call sync from `commitAll`, `loadSnapshot` success path, and import-workspace (bypasses `commit`). Isolation `--verify-isolation` exits before load; do not start a blocker there.
- Never start a second id without stopping the first.
- i18n key in `en`, `pt`, `es`, `zh-Hans`.
