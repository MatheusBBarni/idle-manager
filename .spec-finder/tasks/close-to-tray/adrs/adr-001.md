# ADR-001: Dismissed-farm presence

## Status

Accepted

## Date

2026-09-01

## Context

On Windows, Close (X) destroys every live account view and quits. Minimize keeps ticks but leaves a large window on the taskbar. A shared-PC operator running about 3–6 isolated idle logins cannot dismiss the chrome without ending the farm, and cannot keep the farm without occupying the desktop. Isolation, “running still means ticking,” and “not a bot” stay in force. Microsoft’s notification area is for status of a program with no desktop presence, not a second command strip.

## Decision Drivers

- G-01: dismiss the large window without stopping a live farm
- G-02: ticks continue while dismissed
- G-04: restore and explicit Quit; empty Close still quits
- Win32: tray is presence, not interruption or a command center
- Smallest approach that fixes both failures (accidental quit and desktop occupancy)

## Decision

V1 uses **dismissed-farm presence** on Windows:

- If any account is running, Close dismisses the main window off the desktop and taskbar; those accounts keep running.
- If none are running, Close quits.
- Minimize stays ordinary minimize (taskbar button, ticks continue).
- While a live farm is dismissed, a tray icon shows the running count and offers restore and Quit.
- Quit is also available from Settings while the window is open.
- No tray icon while the window is visible. No tray farm console. No balloons. No start-hidden. No Close=Quit setting.

## Alternatives Considered

### Resident farm icon

- **User value:** Count and tray discoverable even with the window open.
- **Costs/risks:** Persistent icon while the app already has desktop presence; overflow clutter.
- **Why not selected:** Larger than the verified need; fights “tray = no desktop presence.”

### Opt-out close-to-tray

- **User value:** Operators who want classic Close=Quit can turn it off.
- **Costs/risks:** A setting can restore accidental farm-kills (G-01 misses).
- **Why not selected:** The verified problem is Close killing the farm, not a missing preference. Explicit Quit covers leaving on purpose.

## Consequences

### Positive

- `X` no longer ends a live farm.
- Other apps can have the desktop.
- Empty chrome still quits like a normal Windows app.
- Minimize remains a distinct habit.

### Negative and trade-offs

- Close no longer means quit while accounts are running; operators must learn Quit.
- Tray may sit in overflow.
- Restore after dismiss depends on the notification area.
- No always-on icon, no Close=Quit opt-out, no minimize-to-tray.

### Risks and mitigations

- Overflow hides the icon — count on the tray; no V1 balloons; new ADR only if G-01/G-03 miss.
- Cannot find Quit — Quit on tray and in Settings.
- Keyboard restore is weak — accepted for V1; do not keep a taskbar button that undoes dismiss.

## Reversibility

- High. Close can mean quit again. A later ADR can add a resident icon or a Close=Quit setting if dogfood demands it.

## Follow-ups

- Dogfood journal: 3-account and 6-account Windows sessions, 1–2 weeks (G-01–G-04).
- Pop-out windows when chrome is dismissed remain an open, non-blocking question.
